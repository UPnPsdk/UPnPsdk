inline

Test if a socket address is a global unicast address.

This function isn't provided by the system on Unix/Linux platforms as member of the IN6_IS_ADDR test macros. On Microsoft Windows it replaces the imprecise corresponding system function. There it does not check the current specified range for global unicast addresses but only the wide range reservation for future use. For details have a look at Unit Tests 'SockaddrTestSuite.verify_in6_is_addr_*'.

Parameters
[in]a_addrPointer to the address structure of a socket address that shall be checked.

◆ IN6_IS_ADDR_LINKLOCAL2()

bool UPnPsdk::IN6_IS_ADDR_LINKLOCAL2 ( const in6_addr *  a_addr)
inline

Test if a socket address is a link-local address.

The corresponding system functions on all supported platforms are buggy. They do not check that no subnet is specified. For example they accept "[fe80:1::]" as valid, but a link-local address can never have a subnet. For details have a look at Unit Tests 'SockaddrTestSuite.verify_in6_is_addr_*'.

UPnPsdk::inaddr_t
Components of an internet address.
Definition sockaddr.hpp:153

This is a function for special use to prepare input for system calls without brackets. Its results returned in a_addr, a_scope, and a_serv are only useful for this purpose and not meant for general usage. The function only syntactical split the components on its separator '%' and ':'. No syntactical tests are made. For example a scope_id on a global unicast address, or a port number greater 65535 is not valid but also provided in a_scope, resp. a_serv. These tests must be made on a higher abstraction layer.

Parameters
[in]a_addr_svAny string. If it can be interpreted as an ip-address or -name with or without scope_id and/or service (port), its components will be returned.
[out]a_spl_inaddrReference of an internet address structure that will be filled with node, scope_id, and service (port).
